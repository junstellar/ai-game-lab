# 오디세이아 — 프로토타입 설계

> **목적:** 영화 〈오디세이〉를 보기 전에 30분 안에 줄거리의 뼈대를 파악하게 한다.
> 퍼즐은 그 줄거리를 **몸으로 겪게 하는 수단**이지 목적이 아니다.
> **지금은 프로토타입이다.** 예쁘게 만들지 마라. 상태가 읽히고, 즉시 다시 할 수 있고,
> 왜 실패했는지 보이면 성공이다.

## 0. 한 줄 요약

**위협이 훑고 지나갈 자리가 미리 보인다. 한정된 보호 수단을 배치해, 잃을 것을 최소로 만들어라.**

여섯 판이 전부 이 규칙이다. 규칙은 1편에서 한 번만 가르치고, 이후는 같은 규칙의 점점 어려운 표현이다.

## 1. 하드 제약

| 항목 | 값 |
|---|---|
| 총 플레이 타임 | **30분 이내** |
| 판당 시간 | **5분 이내** |
| 판당 재시도(실행 횟수) | **10회 이내** (목표는 표 참조) |
| 스테이지 수 | 6 |
| 기술 | Three.js r160 (`../shunting/vendor/three.min.js` 재사용), 빌드 스텝 없음, 외부 에셋 0 |
| 비주얼 | **단색 도형 + 기본 조명.** 포스트프로세싱·절차적 텍스처·그림자 **금지**(프로토타입) |

## 2. 재시도를 10회 아래로 누르는 3가지 장치

1. **정보를 숨기지 않는다.** 위협이 훑을 자리를 실행 전에 **전부 표시**한다.
   숨기면 시행착오 게임이 되고 재시도가 20회를 넘는다. 긴장은 정보 부족이 아니라 **자원 부족**에서 나온다.
2. **실행 전 편집은 무제한.** 배치를 아무리 고쳐도 재시도로 세지 않는다. `실행`을 누른 것만 1회.
3. **실패 이유를 한 문장으로 보여준다.** "3번 양 아래가 더듬렸습니다 — 2명 발각" 처럼.
   재시도가 시행착오가 아니라 **정보 획득**이 되어야 한다.

## 3. 스테이지 구성

부하 수가 스테이지를 관통한다. 시작 **600명**, 각 판에서 잃은 만큼 줄어 다음 판으로 넘어간다.

| # | id | 제목 | 이야기가 전하는 것 | 목표 재시도 | 시간 |
|---|---|---|---|---|---|
| 1 | `cyclops` | 키클롭스의 동굴 | 탈출, **저주의 시작** | 1~2 | 2분 |
| 2 | `windbag` | 아이올로스의 바람 자루 | 이타카 코앞에서 되밀림 | 2~3 | 3분 |
| 3 | `sirens` | 세이렌의 노래 | 유혹 — 오디세우스만 듣는다 | 3~5 | 4분 |
| 4 | `scylla` | 스킬라와 카리브디스 | **여섯을 내주는 선택** | 4~6 | 4분 |
| 5 | `cattle` | 헬리오스의 소 | 굶주림을 못 막아 **부하 전멸** | 5~8 | 5분 |
| 6 | `bow` | 이타카의 활 | 20년 만의 귀환 | 6~9 | 5분 |

## 4. 공통 모델 — 모든 스테이지가 이걸로 표현된다

```js
Stage = {
  id, title,
  storyIn:  "상황 카드 2~3문장",      // 퍼즐 전
  storyOut: (result) => "결과 카드",   // 퍼즐 후, 결과에 따라 달라짐
  fact:     "실제 신화/영화에서 알아둘 한 줄",  // 결과 카드 하단에 작게

  slots:   [ {id, label, x, y} ],     // 플레이어가 자원을 놓을 수 있는 자리
  crew:    Number,                     // 이 판에 걸린 부하 수
  budget:  { type:'wax'|'sheep'|..., count:Number },   // 한정 자원

  threat:  [ {turn, cells:[slotId], label} ],  // ★ 실행 전에 전부 보여준다
  turns:   Number,

  place(slotId), unplace(slotId),      // 실행 전 무제한
  run() -> { lost:Number, survived:Number, win:Boolean, reason:String },
  optimal: Number                       // 솔버가 계산한 최소 손실 (별 기준)
}
```

**조작 모델은 6판 모두 동일하다:** 슬롯을 탭해 자원을 놓고 → `실행` → 결과를 본다.

## 5. 스테이지별 규칙 (한 문장씩)

**1. 키클롭스** — 양 12마리가 줄지어 있다. 거인이 더듬을 양이 표시된다.
부하를 양 **아래**에 매단다(자원 = 숨을 수 있는 양의 수). 더듬긴 양 아래의 부하는 발각.
*승리 조건: 발각 0명.*

**2. 바람 자루** — 배가 격자 위를 항해한다. 바람 4방향 중 **열 것을 고른다**(자원 = 열 수 있는 바람 수).
매 턴 열린 바람의 합만큼 이동. 암초 칸에 닿으면 손실.
*승리: 이타카 칸 도달.* 실패해도 이야기는 진행된다(부하가 자루를 열어버린다).

**3. 세이렌** — 타임라인 N턴. 각 턴 노래가 닿는 자리가 표시된다.
부하에게 **밀랍**을 배분(자원 = 밀랍 개수)하고, 오디세우스는 **묶는다**.
밀랍 없는 부하가 노래에 닿으면 바다로 뛰어든다.
*승리: 손실 최소 + 오디세우스 생존.*

**4. 스킬라와 카리브디스** — 좁은 해협. 매 턴 좌/우 레인을 고른다.
스킬라 쪽은 **정해진 수**를 잃고, 카리브디스 쪽은 확률이 아니라 **표시된 턴에 전부** 삼킨다.
*승리: 통과. 단 손실 0은 불가능하다 — 이 판은 "덜 잃는 법"을 가르친다.*

**5. 헬리오스의 소** — 굶주림 게이지가 매 턴 오른다. 한정된 식량으로 누구를 먹일지 고른다.
게이지가 한계를 넘은 부하는 소를 잡아먹고, **그 순간 제우스의 벼락으로 전멸**.
*이 판은 이기기 매우 어렵게 설계한다.* 신화대로 전멸하는 것이 기본 결말이고,
살려내면 "신화를 이겼다"는 특별한 결과 카드를 준다.

**6. 이타카의 활** — 도끼 12개가 일렬로 서 있고 각각 구멍 높이가 다르다.
활의 **당김·각도**를 이산값으로 고르면 화살 경로가 미리 표시된다.
*승리: 12개를 모두 통과.* 오디세우스 혼자다.

## 6. 스토리 전달

- 각 판 **전** 상황 카드(2~3문장), **후** 결과 카드. **15초 내 읽히는 분량.**
- 결과 카드 하단에 `fact` 한 줄 — 영화에서 알아두면 좋은 사실.
- 스테이지 사이에 **항해도**: 지중해 약도에 항로가 한 구간씩 이어진다. 부하 수가 함께 표시된다.
- **에필로그:** 이타카 도착 후
  > 호메로스의 오디세우스는 **혼자** 돌아왔습니다.
  > 당신은 **N명**을 데려왔습니다.
  그리고 전체 줄거리 6줄 요약 + 영화 관람 안내.

## 7. 파일 구조

```
static/games/odyssey/
  index.html          셸 (부팅, 캔버스, UI 루트)
  js/00-core.js       → OD.Core  : 상태머신, 스테이지 흐름, 부하 추적, 저장
  js/10-view.js       → OD.View  : Three.js 씬, 단색 도형, 슬롯 렌더/피킹
  js/20-ui.js         → OD.UI    : 상황/결과 카드, 항해도, HUD, 실행 버튼, 재시도 카운터
  js/30-stages.js     → OD.Stages: 6개 스테이지 정의 (공통 모델 §4 준수)
  js/90-boot.js       → OD.Boot  : 부팅 + __SHOT 디버그 API
```

Three.js 는 `../shunting/vendor/three.min.js` 를 그대로 참조한다(중복 배치 금지).
